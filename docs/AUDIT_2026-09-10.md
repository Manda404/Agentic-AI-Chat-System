# Audit and corrections — September 10, 2026

> Historical audit preceding the graph simplification and collaborative team. See [ARCHITECTURE_AGENT.md](ARCHITECTURE_AGENT.md) for the current workflow and [ARCHITECTURE_SIMPLIFIEE.md](ARCHITECTURE_SIMPLIFIEE.md) for the intermediate baseline.

The project had real defects, but the Atlas database was not globally unavailable. Confirmed issues mainly concerned text preservation, reingestion, silent fallbacks, source consistency and misleading diagnostics. Audit fixes were local; no remote data was deleted or reindexed.

The last result indicates unknown provenance, not proof of incorrect vectors. An array field also does not prove that its contents correctly encode all the text. The new diagnostic also checks the index's declared vector dimension.

The real text benchmark found all ten reference titles and ran all ten catalog questions:

| Stage | Precision@5 | Recall@5 | MRR | NDCG@5 |
|---|---:|---:|---:|---:|
| Text retrieval only | 0.22 | 1.00 | 1.00 | 1.00 |

Precision@5 divides by five even when only one document is relevant; 0.22 does not mean that 78% of answers are false. Relevant documents occupied the best ranks on this small known English catalog. These numbers do not evaluate business PDFs, French, ambiguous questions or generated answers.

The full hybrid benchmark was not run: automatic authorization review rejected sending evaluation queries to Hugging Face without explicit approval for that destination. The measurements above used neither Hugging Face nor an LLM. Local tests use service doubles and do not measure production semantic quality.

## Migration before reingesting existing data

New IDs differ from historical IDs. Reingesting into the same collection would leave both old and new records. Reingestion also does not automatically remove fragments from an older version of a changed file.

For a controlled migration, create a separate validation collection and both indexes, ingest original files from the correct owner accounts, wait for queryable indexes, evaluate and compare counts, then switch configuration. Keep the old collection for rollback. This audit did not perform that migration.

Generate the vector-index definition matching `EMBEDDING_DIMENSIONS`:

```sh
cd backend
.venv/bin/python -m app.evaluation.index_health --vector-definition
```

Documents and queries must use the same model and dimension; prefilter fields must be indexed as filters. See the [MongoDB $vectorSearch documentation](https://www.mongodb.com/docs/vector-search/query/aggregation-stages/vector-search-stage/).

## Simplification without losing useful checks

Many classes named Agent are deterministic transformations. The audit grouped responsibilities as:

```text
Understand → Retrieve → Prepare evidence → Answer → Verify
```

Concrete audit simplifications included one document-identity rule, common evidence selection, removing answer caching and unsafe insertion fallback, and stopping ineffective retries. No new agent was added in this audit revision.

The proposed next experiment was a RAG path without CRAG (`CORRECTIVE_RAG_ENABLED=false`) compared with the then-current grader/generator/critic path. Its extra latency and cost needed evidence of fewer incorrect answers. The audit did not change that default without measurement. Later architecture revisions are documented separately.

Semantic reranking also needed comparison with `SEMANTIC_RERANKER_ENABLED=false`: bi-encoder cosine similarity often reuses the vector-search signal. A cross-encoder was another candidate to evaluate before adoption. More agents cannot compensate for an incomplete corpus.

## Risks still open at the time of the audit

- **Chunking/embeddings:** character windows can exceed model token limits, causing provider truncation. Calibrate shorter windows, ideally with the model tokenizer, and reingest into a validation collection.
- **Multilingual content:** default `bge-small-en-v1.5` and some lexical heuristics favor English/ASCII. A multilingual replacement requires regenerating vectors and checking index dimensions.
- **PDF quality:** no OCR, robust table/column reconstruction or structural parsing. Textless PDFs are rejected clearly but not made searchable.
- **Durable ingestion:** no persistent job or transaction spanning files, MongoDB and Redis; batches can partly succeed. Reupload files remain physically stored despite document deduplication. Add retention, per-job status, atomic version replacement and recovery.
- **Existing vector provenance:** all 69 documents lacked `embedding_model`. Equal dimensions do not make different models compatible; new metadata is not an automatic migration.
- **Business evaluation:** the ten catalog cases are easy and title-based. Add document/page/passage ground truth and held-out cases.
- **Grounding:** structural/lexical citations do not establish entailment; critic/fallback scores were uncalibrated. At that revision, rejected answers could still appear with validation notes, requiring a stronger abstention policy. Later revisions changed publication behavior.
- **Performance:** candidate limits were low (text 5, hybrid 8). The benchmark did not evaluate CRAG, compression or final answers; add those measurements before tuning weights and limits.
- **Operations:** `/health` primarily reported initial connections, not current index/model readiness. CLI diagnostics help but do not replace an updated readiness probe. Memory fallback is process-local; shared scope and admin permissions depend on configuration.
- **Frontend reproducibility:** the observed local build used Next 15.2.4 while the manifest requested 15.2.8. That success verified the installed environment, not a clean `npm ci`; CI remains authoritative for the lockfile.

## Evaluation plan

Create 30–50 representative English/French questions covering simple answers, multiple pages, page endings, tables, paraphrases, ambiguity, missing evidence and owner isolation. Annotate expected documents/pages, answers and answer/abstain decisions.

Compare text, vector, hybrid, reranking and CRAG on one versioned corpus. Measure Recall@k, MRR/NDCG, answer and citation correctness, abstention, p50/p95 latency, provider calls and cost. Improvements must preserve existing cases, help difficult cases and justify their cost. Do not derive success thresholds solely from the small catalog.
